# 通道 proxy：用户自有出口

> 无源类（地址来自运行时参数 `--proxy`）；**不进自动降级链**；显式传入即用户已决定。

## 它解决什么

本技能启动时会**清空环境代理变量**（env_guard——沙箱/CI 注入的假代理有前科，会让
"直连明明通了、命令却失败"）。但对**自己有梯子**的用户，这等于把最优路径掐了。

proxy 通道 = 显式声明"用我自己的出口"：

```bash
python scripts/gh.py get owner/repo:README.md --proxy http://127.0.0.1:7890
python scripts/gh.py git push origin main   --proxy http://127.0.0.1:7890
```

- 传入 → **优先级最高、不走链、直接经你的出口**；失败不静默回退（如实报告 + 重新给选项，
  选项里会出现"改走自动链"——由你再决定）
- 不传 → 通道不存在，一切照旧（无人值守/自动化零影响）

## 检测与 offers 的关系（不自动做决定）

环境里检测到代理变量 ≠ 自动使用（环境状态 ≠ 用户意愿，沙箱假代理有前科）。
检测到时代码只做一件事：**探活先于推荐**——用该代理实测一次（≤5s），通了才作为
**结构化选项（offers）**出现在失败报告中（附实测证据与重试命令），
由用户/agent 决定是否采用。gh.py 自身永不交互。

## 凭证边界

**只收无认证代理**（`http/https/socks5(h)://host:port`）。带 `user:pass@` 的地址直接拒绝——
凭证不经过本技能，也不进入日志/JSONL 留痕。本机代理通常无需认证；确需认证代理的用户，
请在系统层配置后以无认证本地端口（如 `127.0.0.1:7890`）接入。
