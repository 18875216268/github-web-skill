# pin · 钉 IP

## 一、方式定义
**不改源，只绕 DNS/线路**：消费资源层供给（`sources/hub.py` 多源聚合+统一测速，每次全新拉取），在单次调用内启动本地 CONNECT 代理（127.0.0.1 随机端口）按域名匹配把 GitHub 域钉到候选 IP。实现：`channel_pin.py`——**纯应用通道**（零获取逻辑）。

## 二、适合的情况
解析被污染、连接被劣化（direct 失败的解药）；git 与 HTTP 通用。浏览器场景用不到它（Agent 侧专用）。

## 三、内部降级链（细粒度）
1. **候选来源**：资源层全量供给（`hub.py`：hosts 清单源 ×8 + DoH ×5 + 官方段安全闸，并发拉取+统一测速）——本通道零过滤（D21）；
2. **候选排序与 failover**：历史好 IP 置顶（`ip_good` 30 分钟 TTL）→ 实测有响应者置前（`ip_alive` 5 分钟 TTL）→ 多轮轮换（`_rotations`，**传输级**换 IP——TCP 连得上但 TLS 被掐的 IP 会白等，必须按"能否传完"换）。

## 四、前提与副作用 / 红线
零系统改动、进程结束即失效；首次拉源+测速有前置耗时（到点用已得结果）。代理内单 IP 连接超时收紧（4s，实测 12s 会吃掉预算）。

## 五、实测记录
2026-09-11 真机：6 域 IP 候选逐条拨测定池；TLS 半途失败历史（转发前必须清两端超时，见 `PinProxy._handle` 注释）。
